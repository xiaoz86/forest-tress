# 附近森林第二版 MVP 规划

来源：2026-05-28 第二次创始团队共创会议、Get 笔记与会议纪要。

## 当前阶段

附近森林已经有一个可访问的线上 MVP：访客可以理解项目主张、查看创造者森林、种下一棵树、上传头像与作品，并通过 AI/规则匹配看到可能连接的人。

第二次会议重新确认：当前最重要的不是继续让新用户填写更多资料，而是先给到一次真实体验。用户需要先在这里感到自己被触动、被看见，才会愿意把个人资料填得更完整。

核心路径：

1. 发现自我：主题冥想、干净提问、深度聆听，让用户先回到自己。
2. 被看见：每棵树可以提供 30-60 分钟微型体验，体验真实产品核心，而不是介绍课程。
3. 共创成长：体验后产生反馈、匹配和进一步连接，逐渐发生线下共创。

## 当前 Supabase 配置

本项目通过环境变量连接线上 Supabase：

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

本地仓库只包含 `.env.local.example`，没有真实生产密钥。生产环境的实际值应配置在部署平台环境变量中。

当前主表是 `node_cards`，字段包括：

- 基础身份：`name`, `city`, `doing`, `topics`, `experience`, `offer`, `seeking`, `product`
- 联系方式：`wechat`, `email`
- 展示与探索：`avatar_url`, `interests`, `beauty`, `seed`, `works`
- 匹配结果：`keywords`, `ai_recommendations`, `ai_recommendations_at`

当前 Storage 使用情况：

- `avatars` bucket：头像上传接口会自动创建 public bucket。
- `works` bucket：作品封面上传接口会自动创建 public bucket。

主题冥想音频和示范体验视频目前先按静态页面区块预留。后续若需要后台管理和动态发布，建议新增 public Storage bucket：

- `meditations`：主题冥想音频
- `experiences`：示范体验、微型体验视频或封面

也可以进一步新增 `experience_products` 表，用于承载每棵树可提供的体验产品。

## 第二版 MVP 页面设计

已经在首页新增两个区域：

1. `#meditations` 主题冥想区
   - 入口文案改为更自然的“给自己一段，安静下来的时间”。
   - 预设三个主题：安顿呼吸、看见此刻的自己、转型期的焦虑。
   - 现在没有实际音频文件时显示“即将开放”；后续补充 `src` 后自动变成播放器。

2. `#experience` MVP 核心体验区
   - 用户侧不直接出现 MVP 术语，改为“体验样本”。
   - 结构覆盖发现自我、被看见、共创生长三个维度。
   - 预留创始人团队 2 分钟示范视频位：先做 45 分钟“积极希望”体验，再剪辑成 2 分钟放在平台。

首页主按钮不再强调“先体验”，改为“走进这片森林”，让体验和加入之间的关系自然发生。

- 用现有静态区块先让团队审核体验路径、语言和页面节奏。

下一阶段：

- 增加体验产品数据结构：标题、主理人、时长、线上/线下、体验入口、反馈摘录、状态。
- 将优质体验展示接入首页滚动位。
- 将体验后的反馈沉淀进节点资料，作为 AI 匹配和共创推荐的依据。

部署协作：

- 当前环境没有安装 Vercel CLI，暂时无法通过 `vercel env pull` 拉取线上环境变量。建议安装 `npm i -g vercel` 后再同步生产配置与部署日志。
