## 一、为什么有 phil-coach

附近森林相信：越是在技术加速的时代，越要回到人——回到一个人如何倾听、如何理解、如何与自己和他人建立关系。而一个人要和别人真实相遇之前，往往需要先和自己坐一会儿。

很多人到了某个阶段，会遇到一些说不清、又放不下的时刻：一个总也想不明白的选择、一段悄悄积着的情绪、一个"我到底想怎么活"的问题。这些话未必适合对身边的人讲，也未必需要一整套课程或一次正式咨询。

phil-coach 就是为这样的时刻准备的一个对话陪伴。它不替你做决定，也不急着把你"修好"，只是先听你把话说完；在你需要的时候，才轻轻递给你一个问题、一点经验，或一个可以往前走的小步。

**它在附近森林里的位置**：附近森林的核心路径是「发现自我 → 被看见 → 共创成长」。phil-coach 承担第一步——让一个人先回到自己。一个更清楚自己在乎什么的人，才更知道想在森林里遇见谁、共创什么。

---

## 二、目标用户

- **主要人群**：正处在人生某个"重量时刻"的成年人，尤其是中年阶段——面对职业转型、意义与方向的追问、关系的变化、说不出口的情绪、需要有人陪着想清楚的选择。
- **共同特征**：不缺信息，缺一个能安心把话说完整、又不被评判的地方；愿意为自己的成长负责，需要的是被支持，而不是被安排。
- **不是为谁准备的**：需要医疗、心理治疗或危机干预的人——这些时刻 phil-coach 会明确建议寻求专业帮助，而不是替代它。

## 三、价值主张

| 别人常给的 | phil-coach 给的 |
|---|---|
| 一个答案 | 一段把话说完整的时间，和一个自己找到答案的过程 |
| 建议与说教 | 先被听见、被接住，再一起看清 |
| 一套标准流程 | 跟着你此刻真实说的话走的对话 |
| 一个角色（咨询/教练/朋友） | 四种陪伴融为一体，随你此刻需要自然切换 |

核心承诺：**议程永远在你**。phil-coach 是过程的专家，你是自己人生的专家。

## 四、四重身份：不是四个功能，是它靠近你的四种样子

phil-coach 默认整合四种能力，不摆角色标签、不让你先选。它读你此刻需要什么，自然成为那一面；只有当你真的想认真被陪着走一程时，才会轻声说一句"我以生命教练的身份，陪你走一段"。

1. **像一位知心的人（知心大姐）**——你心里堵着、或只是想说说话时。先接住、陪着，让情绪可以在，不急着变成道理。
2. **像一位教练（生命教练）**——你卡住、绕不出来时。不塞答案，用一个个问题陪你自己找到它。
3. **像一位顾问**——你需要信息、结构、可比较的选项时。给依据和看法，最后怎么选仍然回到你手里。
4. **像一位走过的人（导师）**——你想听经验、看示范时。先问你的想法，再把经验放到你旁边，让你自己试。

**切换的红线**（越界即失去信任）：
- 情绪浓时不给建议（先做知心大姐，再谈其他）。
- 顾问给完选项必须交回选择权；人生方向级的选择只供料、不替选。
- 导师先问你的想法再开口，不单向讲课。

## 五、核心体验：一段可以一个人走完的十分钟

用户进入 `/phil-coach` 页面后，选择一条"此刻离自己最近的小径"，开始一段实时对话：

| 小径 | 适合的时刻 | 陪伴基调 |
|---|---|---|
| 我想被听见 | 心里堵着点什么，先不急着解决 | 陪伴为主，基本不建议、不推进 |
| 我有点乱，想理理 | 很多事挤在一起，想看清方向 | 教练式探索，让方向自己浮现 |
| 我在一个选择前纠结 | 两边都放不下，来回权衡 | 澄清价值、可控与身体信号；绝不替选 |
| 我想认识此刻的自己 | 停下来，照见现在的自己 | 照见潜能与内在声音，温和的心魔工作 |

**对话原则**（写进系统提示词，贯穿每一次回复）：
- 先同在于故事：先回应你刚说的内容与情绪本身，让你先被听见，再轻轻问一个问题。
- 问题从你的叙述里长出来：留意你反复出现、忽然亮起或沉下去的词，把原词轻轻放回给你——不问模板问题。
- 一次只问一个问题，问题要短。
- 情绪浓时先陪伴，不分析、不推进；被看见之后再问要不要往前走。
- 行动只在时机成熟时才碰，而且轻：一小步、可逆的试探。
- 走到自然段落时，认可你这个人展现的品质（诚实、勇气），而不是夸成就。

对话默认不落库、不留痕，关掉即散——这份轻，本身就是被信任的一部分。

## 六、技术架构

```
用户 → /phil-coach 页面（四条小径入口）
     → PhilCoachExperience（前端对话组件，React 客户端）
     → POST /api/phil-coach（Next.js Route Handler, Node runtime）
          ├─ 危机词拦截（自伤/自杀 → 稳定陪伴 + 转介，不进模型）
          ├─ per-IP 限流（20 次 / 5 分钟，内存滑窗）
          ├─ 组装系统提示词：
          │    BASE_SYSTEM（气质与对话方式）
          │  + COACH_WISDOM（11 个"教练之眼"透镜）
          │  + 知识检索（按主题从 Supabase 取 ≤2 块深度材料）
          │  + 小径意图（llmHint）
          └─ DeepSeek Chat Completions（temperature 0.72，非流式，45s 超时）
     → 返回 reply，追加到对话线
```

**关键文件**（`/Users/xiaoz/codex/forest-tress`）：
- `src/app/phil-coach/page.tsx` — 产品页
- `src/components/PhilCoachExperience.tsx` — 对话交互组件
- `src/app/api/phil-coach/route.ts` — 对话 API（危机拦截、限流、提示词组装）
- `src/lib/philCoach.ts` — 四角色、四小径、意图提示的静态内容
- `src/lib/philCoachWisdom.ts` — 从教练知识库蒸馏的 11 个观看角度
- `src/lib/philCoachKnowledge.ts` — 主题识别 + Supabase 知识检索
- `src/lib/llm.ts` — DeepSeek/Kimi 通用调用封装
- `scripts/ingest-phil-coach-knowledge.mjs` — 知识库入库脚本

**模型**：DeepSeek（`api.deepseek.com`）。密钥仅存 `.env.local`，不入库；`llm.ts` 保留 Kimi 降级路径。

## 七、知识系统：让它有真实的教练功底

phil-coach 的回应不只靠通用模型，还站在一套教练知识体系上：

- **本体（本地）**：27 本教练/心理/正念/领导力经典的知识卡片 + 深度笔记，以及 ICF 核心能力、MCC 级别质感、CPCC 共创式体系、自我实现与心魔工作、教练技术工具箱。
- **蒸馏（提示词内）**：`COACH_WISDOM` 把知识体系压成 11 个"看的角度"——潜能−干扰、共鸣即潜能、冰山、与人不与事、课题分离、控制二分法、目的论、心魔分离、身体先知道、成长型语言、小而可逆的一步。这些是透镜，不是台词：同一时刻只用一个，永不生硬报术语。
- **检索（云端）**：`phil_coach_knowledge`（Supabase，165 个知识块）。对话时从用户消息识别主题标签 → 取最相关的 1-2 块注入提示词，让它"读过书的功底"影响怎么看、怎么问，而不是成段复述。检索失败静默降级，对话永不因知识库不可用而中断。将来流量增长可为该表加 `embedding` 列，升级为 pgvector 语义检索。

## 八、安全、边界与隐私

- **不是医疗/心理治疗/危机干预**：识别到自伤、自杀或即时危险，立即以稳定陪伴回应并建议联系当地急救、可信任的人或专业支持，不进入模型对话。
- **不替你做人生决定**：给视角、结构、诚实的反对意见，最终选择永远是你的。
- **对话隐私**：不写入附近森林数据库，默认不留痕；为生成回复会经由 AI 处理，页面对此保持诚实透明。
- **保密红线（教练伦理）**：创始人本人的真实教练案例、督导笔记、成长日志属于个人与客户隐私，**永不进入网站或云端知识库**——入库脚本硬编码排除这些目录。
- **滥用防护**：公开端点限流，防止直连大模型被刷。

## 九、设计原则（做与不做）

**做**：先听再问；一次一问；跟着人此刻真实说的走；把选择权还给人；对隐私诚实；在能力边界处诚实转介。

**不做**：不摆角色标签；不用打分/流程化开场割裂当下；不连珠炮追问；不说教；不做宏大总结；不替人做决定；不把术语念给用户听。

一句话检验：**这一句，是在支持这个人，还是在替代这个人？**

## 十、未来演进

- **近期**：知识检索上线后观察对话质量；把优质对话沉淀成对自己更清楚的"自我坐标"，反哺附近森林的匹配与共创（需用户明确同意，遵守隐私红线）。
- **中期**：为知识库接入语义检索（pgvector）；对话可选择性地"留住这一段"到用户自己的成长记录。
- **产品家族**：phil-coach 是附近森林"发现自我"的第一个陪伴型产品。未来可能生长出更多面向不同需要的支持产品（如结构化的自我盘点、主题式的深度对话、面向教练同行的督导工具）；它们会共享同一套"先支持人、不替代人"的底层原则。
