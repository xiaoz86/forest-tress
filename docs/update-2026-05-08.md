- **邮箱登录上线**：填节点卡后会收到一封欢迎邮件，里面有一条 7 天有效的「魔法登录链接」。下次回来直接到 `/login` 输入注册邮箱，邮箱里再收一条链接，点开就回到自己的个人页。

## 一、本次更新做了什么

### 1. 邮箱必填 + 唯一
之前邮箱是选填字段，导致一批早期成员既收不到欢迎信、之后也没法找回自己的节点。本次起：

- 提交节点卡时邮箱变成**必填**，前后端双重校验
- 同一邮箱不能注册第二张节点卡（数据库做了大小写不敏感的唯一索引）
- 登录后还可以在个人页改邮箱，改的时候同样会校验唯一性

### 2. 邮箱魔法链接登录
不需要你设密码。流程极简：

1. 你到 [/login](https://nearby-forest.club/login) 输入注册邮箱
2. 服务器查到对应节点 → 生成一条只有它能签发的、7 天后过期的登录 token，发到你邮箱
3. 你点邮件里的「点击登录」按钮 → 浏览器拿到登录态 → 自动跳到你的个人页

技术细节（开发者向）：token 是 `${memberId}.${expiresAt}.${HMAC_SHA256}`，密钥来自服务器环境变量 `AUTH_SECRET`，token 不存数据库，纯靠签名验证；密钥泄露后旋转一次密钥就让所有未消费链接立刻作废。

### 3. 加入即收欢迎邮件
新成员节点创建成功后，会立刻收到「🌱 欢迎加入附近森林」，里面有：

- 你专属的个人页 URL（可以分享出去）
- 一条 7 天有效的登录链接（首次进个人页编辑用）
- 之后随时可以再到 `/login` 申请新的登录链接

### 4. 个人信息可登录后修改
登录的本人、或管理员（小 Z）打开任意创造者页面，会在主体上方看到「编辑个人信息」按钮，展开后可以改：

- 名字 / 城市
- 在做、关注议题（标签式）、兴趣爱好
- 经验与独特性、可以提供、正在寻找
- 微信号、邮箱

> 头像、作品书架的编辑入口此前已经支持，本次保持不变。

### 5. AI 推荐持久化 + 一键重新生成
- 第一次提交节点卡时 AI 给出的推荐结果，会**裁剪后保存**进 `node_cards.ai_recommendations`（去掉对方的私密字段，留下 `id / name / city / doing / avatar_url / matchType / reasons / aiSummary / aiCoCreate`）
- 个人页对**本人 + 管理员**展示一个独立的"AI 为你推荐"卡片区，显示生成时间
- 卡片右上角有「重新生成」按钮，点一下就重新跑一次 AI 撮合并更新快照
- 所有人之外的访客看不到这块——保持推荐的私密性

## 二、节点网络是怎么动态生长的

每个创造者的个人页底部都有一张「关系网络」图——中心是 ta，周围是与 ta 关系最紧密的最多 8 个节点。这张图**不是固定的、随森林整体扩张持续重排**。下面是它的具体规则。

### 1. 不论森林有多大，单张图最多 9 个点

> 中心 1 + 邻居 ≤ 8 = 总数 ≤ 9

设计动机：人脑能瞬间消化的关系密度大约就是这个量级。再多就变星图，弱关系把强关系淹掉。所以即便森林有 1000 棵树，这张图永远只显示离你最近的那一小簇。

### 2. 三档强度：strong / medium / weak

每两个节点之间都有一个匹配权重 `pairWeight(a, b)`（计算方式见下一节"AI 推荐"里的 `scoreMatch`）。权重映射成三档：

| 权重 | 强度 | 视觉 |
|---|---|---|
| ≥ 6 | strong | 离中心更近 |
| ≥ 3 | medium | 中圈 |
| < 3 | weak | 外圈 |

### 3. 邻居选择：强关系优先 + 弱关系兜底
- **第一轮**：把池子里所有跟中心 `pairWeight > 0` 的人按权重从高到低排，最多取 8 个
- **第二轮（兜底）**：如果第一轮取不满 8 个（比如森林还很小），用"弱关系"补足。  
  补的时候不是随机选——而是看每个弱关系节点和**已选邻居**的关联度（`bridging` 分），关联度高的优先。这样图始终看起来是一张网，而不是孤立的点。

### 4. 边怎么连
- 中心 ↔ 每个邻居：**永远画**（哪怕权重为 0，给视觉骨架）
- 邻居 ↔ 邻居：**只在权重 ≥ 1 时画**，弱关系不连。否则会有大量近乎随机的连线把图弄得很糊

### 5. 加入新人时图怎么变
当一个新成员 X 加入森林：

- 任何 `pairWeight(X, 你) > 现有邻居中最低权重` 的成员，下次刷新时会**挤掉那位邻居**进入到你的图里
- 反之你出现在 X 的图里也是同样规则
- 关系网展示的是**实时计算**的，没有缓存——每次访问个人页都按当前数据库重算一次

### 6. 视觉布局
- 圆形画布，中心固定
- 邻居按"角度均匀分布 + 用 id hash 做小幅抖动"防止共线
- 半径取决于 strength 档位：strong 在内圈、medium 在中圈、weak 在外圈

## 三、AI 是怎么推荐 / 匹配的

附近森林同时跑两套撮合机制，分上下两层：

### 第一层：规则匹配（fallback，永远在跑）

文件：[`src/lib/match.ts`](../src/lib/match.ts) 里的 `scoreMatch(a, b)`。它给每两个节点之间打一个分，规则如下：

| 维度 | 加分逻辑 | 加多少 |
|---|---|---|
| **同频** | 共同 topics（议题标签） | 每个共同标签 +3 分 |
| **同城** | `city` 相等 | +2 分 |
| **互补 A** | TA 的 `offer` / `experience` 命中你的 `seeking` / `doing` 关键词 | 每个命中词 +1 分 |
| **互补 B** | 你的 `offer` / `experience` 命中 TA 的 `seeking` / `doing` 关键词 | 每个命中词 +1 分 |

**主要类型判定**：有共同议题 → "同频"；否则有互补命中 → "互补"；否则同城 → "同城"。

中文友好的简易分词（按空格 + 中英文标点切，过滤短于 2 字的词），所以"产品设计"和"设计师"会有交集，但不会精细到义项级别。

### 第二层：AI 重排 + 写自然语言（kimi）

如果配置了 `MOONSHOT_API_KEY`，每次推荐请求会：

1. **先用规则**给所有候选打分排序
2. 取规则分前 8 名（如果连 8 个有分的都没有，就把剩下的人当弱候选喂进去）
3. 把候选 + 中心节点的全部信息**一起给 Kimi**，要求 ta 挑出最值得连接的 1～3 位
4. AI 必须按 JSON 返回，每位带：
   - `matchType`：同频 / 互补 / 同城
   - `reasons`：3 条以内、每条 8-20 字的简短理由
   - `summary`：一句话「为何匹配」（30-60 字）
   - `coCreate`：一句话「可能共创什么」（30-80 字，要落到具体方向、产品形态、活动形式）

> System prompt 大致风格："温暖、具体、克制；不夸张、不奉承；不要解释你是 AI"。这就是为什么你在 doratest 那次撮合里能看到"AI 公益助教 3 周试点"、"30 分钟可复制对话工具包"这种**很落地**的描述——而不是"建议你们多交流"的空话。

5. 返回结果合并回原始节点信息（AI 不能改对方的姓名 / 城市 / 头像，只能补「为何匹配」「可能共创」），存进 `node_cards.ai_recommendations` 字段
6. 失败兜底：如果 Kimi 调用超时 / 返回不能解析 / 没拿到结果，自动回落到第一层的规则匹配

### 还有第三个 AI 任务：关键词

每次提交节点卡时同时跑一次 Kimi 关键词抽取（[`src/lib/keywords.ts`](../src/lib/keywords.ts)），从你的全部文本里提炼 6-8 个最能代表你的关键词，混合覆盖：

- 身份 / 角色（如"独立设计师"）
- 核心专长 / 方法论（如"个人商业画布"）
- 具名项目 / 作品 / 产品（如"附近森林"《随机漫步的进化》）
- 主题方向（如"教育创新"）

这些词存进 `keywords` 字段，作为创造者卡片上的彩色 chip 标签。规则是 AI 必须保留你已填写的 topics + 优先抽取具名项目。

### 调用时机一览

| 触发点 | 关键词 | 推荐撮合 | 关系图重算 |
|---|---|---|---|
| 提交节点卡（首次） | ✓ | ✓（写进 ai_recommendations） | 隐式（下次访问） |
| 个人页点「重新生成」 | ✗（不重抽） | ✓（覆盖快照） | ✓ |
| 编辑资料保存 | ✗ | ✗（需要手动重新生成） | ✓ |
| 任意访客进个人页 | ✗ | ✗（只读现有快照） | ✓（实时算） |

> 设计动机：撮合调用 LLM 不便宜也不快（Kimi 平均 8-15 秒），所以我们**只在用户主动需要时跑**，并把结果留下来。关系图是纯本地计算，可以每次实时算。

## 四、给主理人 / 管理员的快速指引

### 4.1 找回某位成员的节点
让 ta 到 [/login](https://nearby-forest.club/login) 输自己当时注册的邮箱即可，邮箱里会收到 7 天有效的登录链接。

### 4.2 老成员（邮箱必填上线之前注册的）补邮箱流程
如果某成员当年加入时**没填邮箱**，ta 现在没法收到登录链接。处理方式：管理员（小 Z）手动给 ta 关联邮箱，**3 分钟搞定**。

1. **跟成员要 ta 想用的邮箱**（微信发一句即可）
2. 你登录管理员账号：[/login](https://nearby-forest.club/login) 输入 `1826741794@qq.com` → 收登录链接 → 点开
3. 直接访问 ta 的个人页 `https://nearby-forest.club/creators/<节点 id>`，能看到右上角写「管理员视角 · 小 Z」
4. 点主体上方的「**编辑个人信息**」→ 在邮箱字段填 ta 给你的地址 → 保存
5. 让 ta 自己去 `/login` 输那个邮箱 → 收登录链接 → 进自己页面

> 邮箱字段做了**唯一性校验**，不会撞号。如果对方那个邮箱已经被另一节点占用，会立即弹「这个邮箱已被其他成员占用」。

### 4.3 小 Z（你）登录后是全局管理员视角
在任何创造者页面都能直接编辑文字 / 头像 / 作品；AI 推荐区也对管理员可见，可以替成员重新生成。

### 4.4 基础设施
- **数据库迁移已跑过**（2026-05-07 在 Supabase 生产库上）：
  ```sql
  alter table node_cards add column if not exists ai_recommendations jsonb default '[]'::jsonb;
  alter table node_cards add column if not exists ai_recommendations_at timestamptz;
  create unique index if not exists node_cards_email_unique
    on node_cards (lower(email)) where email is not null and email <> '';
  ```
- **Vercel 上需要的新环境变量**已配齐：`AUTH_SECRET` / `SITE_ORIGIN` / `RESEND_API_KEY` / `NOTIFY_FROM` / `NOTIFY_EMAILS`
- **域名 nearby-forest.club 已通过 Resend DKIM/SPF/MX 验证**，所有人都可以收到欢迎信和登录链接

## 五、设计取舍备忘

几个为什么这样做的简短记录：

- **为什么不是密码登录**：节点卡场景里，多数人一年只回来几次。让人记一个密码 = 让人忘一个密码。魔法链接零负担。
- **为什么不是 OAuth（GitHub / 微信）**：附近森林是给"独立创造者"的，不假设你属于任何平台生态。邮箱是最低公约数。
- **为什么 AI 推荐要持久化**：用户反馈里最痛的一句话："那条 AI 推荐我以为只有刚提交时能看一次，回去就找不到了。" 持久化 + 重新生成是最直接的解法。
- **为什么关系图限 8**：见上文第二节。
- **为什么 AI 撮合先用规则筛 8 个再交给 LLM**：上下文 = 钱 = 慢。规则筛过的 8 个候选已经是规则上"最相关"的，让 LLM 把精力花在排序 + 写自然语言上，效果最好。
